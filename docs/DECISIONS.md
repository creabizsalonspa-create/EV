2. Business workflows use Laravel 12.70.1 (MIT) with Composer-locked dependencies. Upstream skeleton v12.12.2 at `945f4e5a9fd3695dc0ee512f497c650fb82cfbb8`; retain upstream MIT license. PHP 8.5.12/Composer 2.10.3 supplied by the digest-pinned Composer image in scripts/php. Do not imply PHP 8.2 compatibility of this lock: some resolved dependencies require newer PHP.
3. Use Blade + browser-native JS for initial responsive web workflows. This avoids Flutter Web's initial toolchain and download footprint for management screens and uses same-origin CSRF-protected sessions. Flutter remains required for customer/vendor Android/iOS; native authentication and client contracts are not implemented yet. This choice is provisional pending usability/accessibility evaluation.
4. SQLite is a local development database. PostgreSQL concurrency and deployment remain unverified. DB uniqueness prevents two confirmed fixed-slot bookings; production needs multi-connector inventory, expiry, occupancy controls and concurrent Postgres acceptance tests.
5. GitHub API requests return `Forbidden`; scoped Git transport succeeds. Composer archives use GitHub codeload URLs for the same locked refs; no package checksum, signature, or TLS bypass. The container trusts the host CA bundle via a read-only mount. This metadata URL change is recorded in composer.lock; future updates may need the same URL normalization until API egress is available.

7. No CodeCanyon source or license was supplied, so none is used. No map, PSP, station-data or operator credentials are required for the implemented local workflow.
8. Simulation endpoints are explicitly named and cannot send physical commands or collect money. Fixed-rate integer arithmetic is only a test fixture. It is not billing-grade reconciliation or tax invoicing.

9. Identity continuation: use Laravel's MustVerifyEmail contract, VerifyEmail notification and EmailVerificationRequest rather than a custom email token protocol. Request sending explicitly so an unavailable mail provider cannot break registration. Preserve a guest's privacy by asking them to sign in and reopen the mail link; do not persist bearer-like signatures in sign-in URLs. Audit the first verification within the same database transaction. Local log delivery is development evidence only; verification does not automatically approve vendors or gate simulated charging.
10. Web appearance: a small same-origin `theme.js` initializes Light/Dark/System before CSS to prevent flashing the wrong palette. Semantic CSS variables style all shared controls, including recovery/verification pages; browser storage contains only the appearance choice, never account data or signed links. Keep the native app and full premium design scope outstanding.
