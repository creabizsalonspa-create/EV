# Company-scoped recorded CSMS meter history

This read-only continuation extends the verified staff session view integrated in PR191 at151acd73. It uses the existing `charging.read` grant and exact-version owner/recipient consent. It neither delegates charger controls nor calculates consumed/billed energy, issues invoices or creates a financial source of truth. A read cannot dispatch, reconcile or replay a command.

## API and authority

`GET /api/vendor-ops/companies/{company}/charging-sessions/{session}/meter-history` and the existing authenticated native mount `/api/v1/vendor-ops/companies/{company}/charging-sessions/{session}/meter-history` expose the same contract. Routes use the project-standard bounded numeric identifiers; supported response identities are positive safe integers. `page` is1–100000, `through` is0–9007199254740991. Pages contain25 rows, descending retained event ID.

Both the existing session list and history use the same transactional authority check: fresh active account, matching role/password/auth epoch, locked current company, verified active accepted membership and no Admin security hold, or existing owner/current-Admin authority. The session must belong to a currently owned station linked through the existing unique company/site relation. Same-owner other-company and foreign sessions are excluded. The historical CSMS link must reference a binding on that same station and a recognized1.6/2.0.1 protocol. Binding/protocol credentials, wire identifiers, transaction IDs, event IDs, fingerprints, customer/vehicle/booking identity and monetary columns are never selected for the DTO.

Only existing `csms_inbox_events` with `outcome=applied` and type `started`, `meter` or `ended` are included. Rejected/stale events are not presented as applied measurements. Source rows are not created, rewritten, repaired or backfilled by this endpoint. A session without an eligible link has an explicit empty `NO_RECORDED_CSMS_LINK` result; a local application-simulator total is never turned into a fabricated historical reading.

The first read captures the highest retained event ID. Paginator self-links retain the fixed `through_id`; session-list self-links also preserve their validated status filter. Subsequent pages pass the cursor; later appends are excluded until explicit Refresh. This is a bounded retained-event window, not a claim of complete historical coverage. The canonical ingestion path serializes same-link writes; administrative deletion/rebinding can invalidate an old cursor and requires a new read. A future cursor beyond current retained history fails422 rather than silently expanding the window.

Rows expose only event ID, sequence, recorded kind, cumulative counter Wh, source-record timestamp and receipt-record timestamp. Unsafe counters/identifiers or unreadable stored times fail422 without coercion or billing. The cumulative register can be much larger than consumed session Wh; the interface makes that distinction explicit and performs no delta or price calculation.

The response identifies company/session, fixed cursor, source linkage/protocol, `RECORDED_APPLIED_CSMS_EVENTS` coverage and read `as_of`. `history_complete`, `billing_authority`, `physical_energy_verified`, `commands_sent` are false and `network_requests` is0. Cache-Control is `no-store, private`. UTC timestamps reflect actual retained database values. Existing PostgreSQL inbox columns round timestamps to retained whole seconds, whereas SQLite fixtures can retain fractions; the API never reconstructs discarded wire precision. Timestamp formatting is not proof of source-clock accuracy, freshness or physical hardware.
