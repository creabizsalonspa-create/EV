# Source-backed command outcome reconciliation

This implements simulator command recovery from already authenticated and applied inbox events. It never resends a start/stop, creates a remote command, fetches new source data, fabricates a source event or proves charger acceptance. Existing CSMS bridge and dispatcher non-production feature guards remain enabled.

After an inbox transaction commits, the bridge examines its exact session-linked start/stop commands. A started event with sequence0 and established source transaction can resolve start intent; an applied ended event and stopped session can resolve stop intent. Binding/station/identifier/protocol and command/session lineage must match; closed-without-dispatch and cancelled requests cannot recover. Missing, stale or unapplied evidence changes nothing.

One immutable `command_source_observations` record per command references the accepted inbox event and retains prior status/failure, observed started/ended state and `command_acceptance_verified=false`. Status becomes `source_observed`. This says the requested state is evidenced, not that a particular command caused it. Original transport confirmation remains separate. Ingest duplicates can complete an interrupted follow-up without duplicating evidence or invoices.

The dispatcher reconciles committed evidence before any claim. A final in-transaction source-state check blocks a start/stop already observed even if another process committed after preflight. Transport replies update only a still-dispatching command, so a late successful response or timeout cannot overwrite source evidence. Uncertain starts without source evidence remain unresolved and are never automatically replayed.

Versioned bearer routes now also expose owned CSMS start and stop with the same source/window admission rules as cookie routes. Authenticated POST `/api/charging-sessions/{id}/reconcile` and `/api/v1/...` permit only the owning customer, station-owning vendor or Admin. Authorization precedes proof processing. It returns the count, summary, `source=authenticated_applied_inbox_only`, `network_requests=0`, and `command_acceptance_verified=false`. Customer/vendor web and Flutter show transport state separately from source outcome, provide an explicit evidence-reconciliation action, safe loading/errors and English/Arabic disclosure. This action does not poll CSMS or convert absence of evidence into a failed transaction.

`php artisan csms:reconcile-commands --limit=100 --after=0` provides a bounded non-production recovery scan after a process restart; limits1–1000, optional ID cursor. It does not invoke the consumer or dispatcher. Operators must run the authenticated observer separately to collect new events. There is no unconditional background device dispatch. Migration rollback refuses populated evidence outside tests.

Tests cover lost HTTP acknowledgement, a late successful reply, interrupted post-commit processing, exact replay, private scope, no evidence/no mutation, unchanged one-invoice finalization and no network sends. A PostgreSQL race runs two independent PHP workers behind a barrier and delayed observation insert, proving one observation and no additional charging/finance records. Browser test uses a clearly synthetic local inbox fixture; both actual CitrineOS protocol flows separately assert source-observed start/stop after continuous observer restart and preserve final meters and simulated finance.

Still unfinished: production source authentication/provisioning/token revocation, timeout-with-no-evidence triage, authorized reconnect/recovery policy against real chargers, distributed observer ownership, physical meter acceptance and full OCPI remote command interoperability. `source_observed` is not production hardware acceptance. Maps and remaining customer/vendor/Admin/commercial workflows remain tracked product work.
