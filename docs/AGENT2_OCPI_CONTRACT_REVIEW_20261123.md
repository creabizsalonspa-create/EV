# Agent 2 — OCPI internal contract-evidence review (23 November 2026)

## Status and original scope

This is an **implemented software candidate** for original requirement **6.4.8 (contractual onboarding software)**, not a whole-atom completion or production-acceptance claim. It adds an optional internal review gate for new authorizations and an auditable, private operator-document review workflow. A human-entered reference and SHA-256 digest are **not proof of a legal signature, executed agreement, real partner acceptance, regulatory clearance, remote-command permission, or payment authority**.

Agent 5 retains exclusive integration control. Do not merge until all mandatory exact-head Platform/PostgreSQL/CSMS/Native/Staging CI passes on the source and resulting integration SHA. No real network mutation or live charging/payment was authorized by this work.

## API and software surfaces

- `GET /api/ocpi/providers/{id}/contract-review` (also under authenticated `/api/v1/ocpi`): current Admin or owning active vendor, private/no-store. Reports `missing`, `internally_reviewed`, or `revoked`, current revision, owner-validity, review expiry and deliberately false external acceptance/signed-contract/live-roaming/payment flags.
- `POST /api/ocpi/providers/{id}/contract-review`: current active Admin only (native personal access tokens cannot become Admin). Require explicit `decision=review|revoke`, 15–1000 character reason, `expected_revision` optimistic revision, and secure `idempotency_key`. A review additionally requires a sanitized internal case reference, 64-character lowercase SHA-256 digest, and a date no more than three years forward. Never accept a raw document URL, file or credential in this API.
- `GET /api/ocpi/providers/{id}/contract-review/history?page=N`: bounded 25-row owner-scoped pagination. Admin can review decrypted internal notes and digests; vendors see only decision state, revision and timestamp, with no prior-owner rows or sensitive review material. All reads are private/no-store.
- Append-only `ocpi_partner_contract_reviews` table: provider/owner/reviewer identities, monotonic unique revision, deduplicated idempotency identity, digest and reference, encrypted human note, UTC submission clock. Failed/revoked/stale operations commit no record or audit.
- Web `roaming.js`: bilingual English/Arabic provider review status and explicit Admin forms, manual-only submission with fresh cryptographic idempotency identity, no automatic retry on an uncertain response, conservative false-claim rejection, old-account content clearing and text-only rendering.
- Customer discovery/roaming map and saved-location visibility: when the review policy is enabled, every source-provider SQL selection and the later unified-search hydration uses the latest revision tied to the current *active vendor owner*. Expired/revoked/old-owner records disappear from public discovery and provider labels. Existing saved preferences remain as harmless tombstones with no location/coordinates/timestamps while blocked; removal never requires a review. No provider/charger network request is made to decide eligibility.
- CPO publisher authority now checks the same owner-bound review *inside* its transaction before private publication history reads, source mutation, authenticated peer catalog delivery, sandbox push claims or reconciliation. A previously active credential and previously negotiated receiver cannot bypass a missing, expired, revoked or previous-owner review. Default-off legacy sandbox behavior is preserved; no remote peer request is sent by the guard. The `OcpiCpoAdminAuthorityTest` synthetic active-link regression covers default-off behavior, expiry, provider reassignment, fenced reads and writes and absence of network/financial effects.
- Backend optional config `OCPI_CONTRACT_REVIEW_REQUIRED=true`: newly created providers start **pending** and must have a current owner-bound unexpired internal review before Admin can set `authorized=true`. The same current-owner, current-date gate now also blocks outbound OCPI reads, negotiations, sandbox commands and CPO push dispatch through `PartnerClient::assertCurrent()`; managed register/rotate `CredentialExchange`, incoming prepare/accept `IncomingEnrollment` and authenticated peer GET/PUT `OcpiProtocolCredentialsController` are likewise gated. An expired review or transfer of ownership cannot acquire new peer capabilities, even for a previously authorized provider. **Explicit unregister and authenticated peer DELETE remain possible** so that closing the relationship does not require accepting a new contract. A currently authorized provider must be separately deauthorized before an enforced internal review can be revoked. Default remains `false` until migration, operational policy, real legal approvals and integration verification are ready; the default does not imply contractual conformance.

## Boundaries and gaps

This is internal **software governance**, not a signed contract workflow with document-storage signature verification or a verified OCPI network relationship. Existing authorized providers are **not automatically reclassified** when the optional gate is enabled. Outbound requests and incoming credential lifecycle are now gated for new operations, but already in-flight network exchanges cannot be cancelled, and external adapters need individual certification and operator-approved lifecycle policy before any live onboarding rollout. Review expiry is not itself a remote stop or a physical charger command.

The partner catalog, availability and settlement evidence continue to be explicitly synthetic or source-reported; no customer charging or financial permissions are granted.
