# Provider dispute operations

`ExternalDisputes`, `StripeTestDisputes`, migration `2026_10_28_210001` and `ExternalDisputesController` extend the canonical payment/invoice/case foundation. They do not implement a second payment ledger. This is a **Stripe TEST HTTP contract**, not verified merchant access, card-network acceptance or live chargeback processing. No live keys or production mutations are accepted.

## Provider truth and settlement holds

Configure the existing `STRIPE_TEST_SECRET` and `STRIPE_TEST_WEBHOOK_SECRET` through secret management. Register the **separate** POST `/api/disputes/stripe-test/webhook` endpoint for `charge.dispute.created`, `.updated`, `.closed`, `.funds_withdrawn` and `.funds_reinstated`. Do not replace existing payment/refund callbacks. Raw-body timestamp/HMAC verification uses the existing pinned Stripe TEST verifier. Unsupported, stale, live-mode and changed-payload events fail closed.

A callback is a notification to inspect the exact dispute using GET `/v1/disputes/{dp_id}`. GET `/v1/charges/{ch_id}` then binds the exact captured charge to its PaymentIntent and existing captured checkout; amount/currency must match and dispute amount cannot exceed capture. Unrelated charges/checkouts, unknown statuses and changed historic economics are rejected. The invoice lock serializes competing callbacks and canonical settlement/refund writes. Duplicate event IDs with different content return409; legitimate duplicates create no new case or accounting entry. Dispute economics and event history have database immutability protections.

Each provider dispute links **one existing `gateway_cases` record**. Open, review and lost statuses retain the existing settlement hold, including after a late dispute against an already paid settlement. Authoritatively observed `won`/`warning_closed` releases this dispute's hold; other refund/case holds continue. Manual legacy case resolution cannot bypass a provider-owned hold. New PSP refunds are blocked under the same invoice lock while an active/lost provider dispute holds that invoice, preventing an independent second return of captured funds; previously confirmed operation replays remain idempotent. Provider `lost` does **not** manufacture a customer refund or silently change the canonical ledger. `chargeback_accounting=NOT_POSTED_REQUIRES_FINANCIAL_RESOLUTION` explicitly exposes the unresolved economics. Automatic chargeback allocation/posting, fee accounting and a controlled release after approved canonical adjustments are remaining independent software, not just missing credentials. Existing administrator-approved settlement adjustments can record reviewed vendor recovery, but this module does not automatically create or approve one.

## Private authenticated contracts

Routes mount within existing authenticated/throttled cookie and `/api/v1` financial groups. Customer sees own invoices, vendor sees own invoices, admin sees all; foreign IDs return404. No provider charge IDs, raw evidence, encrypted payload, request keys or fingerprints are returned. The shared API private-cache middleware remains required.

| Endpoint | Behavior |
|---|---|
| GET `commercial/external-disputes?page=1` | Scoped25-row page; optional `attention=1` filters response-needed, lost and uncertain evidence operations |
| GET `commercial/external-disputes/{id}` | `{dispute, events, evidence_submissions}`; immutable event summaries; admin-only sanitized submission records |
| POST `commercial/external-disputes/{id}/reconcile` | Admin-only authoritative GET; no payment mutation; recover an accepted uncertain evidence submission from exact returned fields |
| POST `commercial/external-disputes/{id}/evidence` | Admin-only `{idempotency_key, submit:boolean, evidence:{...}}`; stable key bound to dispute/evidence/submit |

`dispute` includes invoice/case/checkout IDs, currency, invoice minor-unit precision, amount, status/reason, provider observation, deadline, `deadline_passed`, `settlement_hold`, `requires_financial_resolution`, and explicit TEST/no-real-money evidence. Provider exception dates are UTC. Immutable historical invoice economics remain the authority.

Only Stripe's **text** evidence fields are supported: `product_description`, `service_date`, `refund_policy_disclosure`, `refund_refusal_explanation`, `access_activity_log`, `uncategorized_text`; each nonempty and bounded5000 bytes. Unknown fields and raw card fields are rejected. Stripe `customer_communication`, `refund_policy` and similar file-ID fields are intentionally excluded; authenticated file upload, malware scanning, retention/consent policy and provider File API submission are remaining software. Text can still contain personal information: operator access/retention and privacy review are required.

Before submission, read-only reconciliation establishes the current provider state/deadline. The durable encrypted, payload-bound operation commits **before** POST `/v1/disputes/{id}` with a deterministic PSP idempotency key. Three-minute leases fence overlapping submits. A failed response remains `uncertain`, blocking replacement identities; an expired lease permits retry only with the same payload/key, within a conservative23-hour retention window and an open provider deadline. Beyond this, inspect/investigate instead of blind POST. Success requires exact returned evidence fields; final submit additionally requires provider submission evidence and an appropriate review/closed state. Read-only reconciliation can recover accepted evidence after a lost response/process crash; no raw provider response is persisted. Operation payload terms cannot be changed/deleted in SQL; operational state can advance.

## Verification and remaining work

`ExternalDisputesTest` covers invalid HMAC, replay/mutation, exact capture/currency binding, customer/vendor isolation, provider-owned hold protection, won/lost behavior without cash mutation, bounded encrypted idempotent evidence, deadline enforcement, lost-response read-only recovery, forbidden live keys/evidence, and database evidence immutability. Two independent-process PostgreSQL race sources verify same/distinct events share one canonical dispute/hold. Executed counts/logs belong to the Agent1 checkpoint; source presence alone is not evidence of passing PostgreSQL, browser or real PSP acceptance.

A bounded GET-only worker is available as `commercial:reconcile-disputes --provider --limit=25` (maximum100). Explicit `--provider` opt-in is required; no default network call occurs. It advances operational inspection slots on errors without claiming a new authoritative provider observation. Attention/failure returns a failing command status; it never submits evidence or moves funds. Registered scheduling/deployed cron and external alerts require separate operational setup.

The actual-Laravel `tests/external-disputes.cjs` browser uses a strictly local/testing SQLite synthetic fixture. Provider responses are faked only during CLI ingestion, never through a server bypass. It checks customer/vendor/admin history, foreign404, masked identities, evidence-control authorization, EN/AR RTL, eight light/dark390/768/1440 screenshots and logout cleanup. `tests/external-disputes-ui.cjs` separately simulates APIs to check literal evidence text, error handling, stable same-key retry across inspection, lazy reads and private draft cleanup. These browser component contracts are not provider acceptance.
