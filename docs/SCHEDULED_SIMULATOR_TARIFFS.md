# Scheduled simulator tariff versions (3.4.7 partial)

This is an opt-in, API-only implementation of time-based price changes. It uses the existing immutable tariff-version and session-consent machinery. It is disabled by default and is never available in production. No live pricing, automatic demand pricing, legal permission, or commercial acceptance is established.

Set `SCHEDULED_SIMULATOR_TARIFFS_ENABLED=true` only in an isolated local/testing environment after review. An authenticated current administrator can POST `/api/stations/{station}/tariffs/schedule` (same authenticated finance routes). The request requires `effective_at` (strict UTC second, 60 seconds to 30 days ahead), `expected_active_tariff_id` (nullable only when no active tariff exists), `expected_currency`, `expected_minor_units`, integer `rate_minor_per_kwh`, `tax_bps`, `commission_bps`, and a UUID `idempotency_key`. It creates one immutable complete future tariff; retries with the same payload return its original receipt. A second activation instant is refused. GET on the same route returns the current active and latest pending tariff to a current administrator, privately. To correct the pending rate, POST the complete replacement values with the exact existing `effective_at`, the currently returned `expected_pending_tariff_id`, the expected active ID and a new UUID. The original record is preserved; only the newest version at that instant activates. Stale correction IDs and different activation times are refused. History remains available through the existing authenticated tariff history. The future entry does not change the active price until its timestamp.

The scheduled version explicitly includes tax and commission. Immediate publication of any new tariff is blocked while any future version remains pending (including after the scheduling flag is disabled). Prior identical receipt retries remain available. This prevents a later scheduled version silently reversing a new tax, rate or commission. A correction retains the original activation time; cancellation and rescheduling are not implemented. Once the scheduled instant arrives, ordinary immediate publishing resumes. Recurring windows, vendor delegation, browser/Flutter scheduling interfaces and full commercial/regulatory acceptance are not implemented. Do not enable the feature in an operator-facing shared environment until those workflows and current-price display behavior have been independently validated.

Existing price consent must match the active tariff at start; a change can require a new estimate/consent. A created session retains its original immutable tariff snapshot. The feature does not dispatch charger commands, initiate payments or create invoices by scheduling a rate. No original requirement completion is claimed until full scope and exact-source validation are established.
